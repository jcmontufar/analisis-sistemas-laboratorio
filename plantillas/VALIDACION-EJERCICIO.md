# Prevalidación de ejercicio

Completar antes de generar una solución. Marcar “No aplica” con justificación; no marcar como correcto lo que solo pasó sintaxis.

## Entrada

- [ ] Enunciado original disponible y conservado.
- [ ] Tipo de ejercicio/artefacto identificado.
- [ ] Información suficiente para comenzar.
- [ ] Datos ambiguos y faltantes registrados.
- [ ] Fuentes académicas pertinentes identificadas con página, diapositiva o línea.
- [ ] Se determinó si el encargo es DERCAS o un ejercicio individual.

## Análisis

- [ ] Actores identificados.
- [ ] Entidades externas o de datos identificadas.
- [ ] Procesos identificados.
- [ ] Responsables identificados.
- [ ] Entradas y salidas identificadas.
- [ ] Datos identificados.
- [ ] Decisiones y alternativas identificadas.
- [ ] Reglas de negocio identificadas.
- [ ] Relaciones y dependencias identificadas.
- [ ] Suposiciones separadas de hechos.

## Generación

- [ ] Herramienta seleccionada y justificada.
- [ ] Archivo fuente editable creado.
- [ ] Nomenclatura consistente con el análisis.
- [ ] Exportación SVG creada, cuando corresponde.
- [ ] Exportación PNG creada, cuando corresponde.
- [ ] Todos los archivos están en la carpeta del ejercicio.

## Revisión

- [ ] Corresponde al enunciado.
- [ ] Corresponde al material académico aplicable.
- [ ] Las reglas académicas están separadas de convenciones técnicas.
- [ ] Sintaxis y estructura validadas.
- [ ] Coherencia conceptual revisada por una persona.
- [ ] Legibilidad y exportación completa verificadas visualmente.
- [ ] Restricciones específicas del catedrático comprobadas.
- [ ] Consistencia con artefactos dependientes revisada mediante `base-conocimiento/MAPA-DEPENDENCIAS.md`.
- [ ] Limitaciones y validaciones humanas pendientes documentadas.
